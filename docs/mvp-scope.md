# 比特海盗的码头 · MVP 范围

## 这一版要验证的事

有人愿意把用 AI 做出的作品投到码头；船长能低成本审核；作品能被公开浏览和分享。

## 本期交付

- 公开作品瀑布流：首页只读取已通过的作品，支持按标签筛选。
- 作品详情：完整介绍、航程录、标签、外部作品链接与分享入口。
- 投稿：单张封面上传、作品信息提交、作者资料本地记忆、明确的待审核反馈。
- 审核后台：密码受 Edge Function 保护；查看待审、通过/驳回、填写驳回原因、人工选择标签。
- 数据基础：Supabase Postgres、Storage、RLS 与 Edge Function 示例。
- 分享基础：稳定的作品详情 URL；预留 Open Graph 元数据的服务端/构建期接入点。

## 有价值，但刻意不在本期做

| 能力 | 用户价值 | 暂缓原因 | 触发条件 |
| --- | --- | --- | --- |
| 审核通知与补交 | 让投稿形成闭环 | 需要邮件通道与重提状态设计 | 每周出现 3 个以上驳回或补交需求 |
| 自动分享卡片 | 提升小红书/微信外链识别度 | 需要图片渲染服务或 Worker | 已有稳定作品链接和首批分享数据 |
| AI 标签建议与风险提示 | 减少船长审核时间 | 需要模型密钥、提示词与人工兜底 | 每周审核超过 10 件作品 |
| 点赞、收藏、访问量 | 给创作者反馈、帮助排序 | 需要反滥用与隐私说明 | 首页作品达到 30 件以上 |
| 作者账号与作品管理 | 作者可编辑与查看状态 | 登录、找回、权限带来维护成本 | 投稿人提出高频修改需求 |
| 评论、私信、积分 | 社区互动 | 内容治理成本远大于 MVP 收益 | 有明确社区运营人力和规则 |
| 个性化推荐 | 更高发现效率 | 冷启动下没有足够行为数据 | 有稳定访问与互动数据 |

## 不做的原则

任何功能都至少服务以下一项才进入排期：提高有效投稿量、降低审核成本、提升作品分享转化。否则先记录，不开发。
